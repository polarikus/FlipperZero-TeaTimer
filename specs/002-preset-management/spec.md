## User Scenarios & Testing *(mandatory)*

### User Story 1 - Выбор пресета через стандартный экран выбора файла (Priority: P1)

Пользователь открывает приложение, попадает в знакомый системный экран выбора файла (тот же, что в других приложениях: список файлов с иконками, переход по папкам, прокрутка), находит нужный `.tea`-файл и открывает его. Приложение показывает карточку пресета с параметрами и запускает заваривание.

**Why this priority**: Это замена ранее предложенного собственного списка: знакомый системный экран снижает стоимость разработки и делает поведение предсказуемым. Без выбора пресета приложение не работает.

**Independent Test**: Положить в каталог приложения три `.tea`-файла, открыть приложение, зайти в выбор пресета и открыть файл — должна показаться карточка с параметрами из файла.

**Acceptance Scenarios**:

1. **Given** в каталоге приложения есть `.tea`-файлы, **When** пользователь выбирает «Presets», **Then** открывается системный экран выбора файла, уже находящийся в каталоге приложения, и в нём видны только `.tea`-файлы и подкаталоги.
2. **Given** открыт экран выбора файла, **When** пользователь открывает `.tea`-файл, **Then** показывается карточка пресета: название, граммовка, время первого пролива, приращение, рекомендованное число проливов, действие Start.
3. **Given** открыта карточка пресета, **When** пользователь нажимает Start, **Then** поведение таймера полностью соответствует спецификации 001 (отсчёт, сигнал, инкремент счётчика, превышение лимита без блокировки).
4. **Given** пользователь находится в подкаталоге каталога приложения, **When** он возвращается назад, **Then** он оказывается в родительском каталоге, а затем — в главном меню приложения.
5. **Given** в каталоге лежат файлы с другими расширениями, **When** открыт экран выбора файла, **Then** эти файлы не показываются.

### User Story 2 - Создание нового пресета прямо на устройстве (Priority: P1)

Пользователь пробует новый чай и хочет сразу завести пресет, не доставая компьютер. Он открывает «New preset», вводит название экранной клавиатурой, затем по очереди вводит граммовку, время первого пролива, приращение и число проливов цифровыми полями, видит сводку и сохраняет. Пресет сразу доступен для заваривания.

**Why this priority**: Это явное дополнение от пользователя; без него пресеты можно создавать только с ПК, что ломает сценарий «попробовал чай — сразу завёл пресет».

**Independent Test**: Создать на устройстве пресет с названием `Test Tea` и параметрами 5.0 / 20 / 5 / 6, сохранить, затем открыть его через выбор файла и убедиться, что параметры совпадают, а файл появился в каталоге приложения.

**Acceptance Scenarios**:

1. **Given** открыто главное меню приложения, **When** пользователь выбирает «New preset», **Then** открывается экран ввода названия со стандартной экранной клавиатурой и предзаполненными значениями остальных полей.
2. **Given** введено название, **When** пользователь подтверждает его, **Then** последовательно запрашиваются числовые значения: граммовка на 100 мл, время первого пролива (с), приращение (с), рекомендованное число проливов.
3. **Given** все значения введены, **When** пользователь подтверждает сводку, **Then** в каталоге приложения создаётся `.tea`-файл с этими значениями, а пользователь видит сообщение об успешном сохранении с именем файла.
4. **Given** пресет только что сохранён, **When** пользователь открывает «Presets», **Then** новый файл виден в списке без перезапуска приложения.
5. **Given** пользователь создаёт пресет, **When** он отменяет ввод на любом шаге, **Then** никакой файл не создаётся и он возвращается в главное меню.

### User Story 3 - Защита от неверного ввода и конфликтов файлов (Priority: P2)

Пользователь ошибается при вводе: оставляет имя пустым, вводит нулевое время, забывает про допустимые пределы, или в каталоге уже есть файл с таким же именем. Приложение не сохраняет некорректный пресет и понятно объясняет, что не так.

**Why this priority**: Форма на устройстве с маленьким экраном и цифровым вводом — источник ошибок; без проверки приложение начнёт создавать файлы, которые само же пропустит при чтении.

**Independent Test**: Попытаться сохранить пресет с пустым названием, затем с нулевым временем первого пролива, затем с названием, для которого уже есть файл, — в каждом случае должно появиться понятное сообщение, а файл не создаваться (или создаваться под новым именем).

**Acceptance Scenarios**:

1. **Given** поле названия пустое, **When** пользователь пытается перейти к следующему шагу, **Then** показывается сообщение о необходимости ввести название, ввод остаётся на этом же шаге.
2. **Given** числовое значение выходит за допустимые пределы, **When** пользователь подтверждает его, **Then** показывается сообщение с допустимым диапазоном, и значение можно исправить.
3. **Given** файл с таким же именем уже существует, **When** пользователь сохраняет новый пресет, **Then** приложение не перезаписывает файл молча: создаёт файл с уточняющим суффиксом либо явно спрашивает о перезаписи.
4. **Given** нет доступа к SD-карте или запись не удалась, **When** пользователь сохраняет пресет, **Then** показывается сообщение об ошибке записи, а введённые значения не теряются.

### User Story 4 - Правка существующего пресета на устройстве (Priority: P3)

Пользователь заметил, что время первого пролива подобрано неудачно, и хочет поправить его прямо на устройстве.

**Why this priority**: Естественное продолжение создания пресета с почти тем же набором экранов, но не является обязательным для запуска «создай и завари»; при отсутствии правки пользователь может удалить файл и создать заново.

**Independent Test**: Открыть карточку существующего пресета, выбрать правку, изменить одно значение, сохранить — файл обновлён, остальные значения не изменились.

**Acceptance Scenarios**:

1. **Given** открыта карточка пресета, **When** пользователь выбирает «Edit», **Then** открывается та же форма, что и при создании, с текущими значениями пресета.
2. **Given** форма правки заполнена, **When** пользователь сохраняет, **Then** обновляется исходный файл, а имя файла не меняется.
3. **Given** пользователь изменил название чая, **When** он сохраняет, **Then** файл остаётся с прежним именем, а новое название записывается внутри файла.

---

### Edge Cases

- **Каталог приложения отсутствует**: при открытии «Presets» показывается сообщение с путём и подсказкой; при сохранении нового пресета каталог создаётся автоматически.
- **В каталоге нет `.tea`-файлов**: экран выбора файла пуст; пользователь может вернуться и создать пресет через «New preset».
- **SD-карта не вставлена или извлечена во время ввода**: сообщение об ошибке; введённые значения сохраняются в форме до выхода из неё.
- **Название длиннее допустимого** (более 24 символов): ввод ограничивается по длине, а на экране название обрезается многоточием.
- **Название с нелатинскими символами**: вводятся только латинские буквы, цифры, пробел и `_`; остальные символы не добавляются.
- **Спецсимволы в названии для имени файла**: пробелы и недопустимые для имени файла символы заменяются на `_`, регистр приводится к нижнему, при совпадении добавляется суффикс `_2`, `_3`.
- **Дробная граммовка**: разделитель — точка (`5.0`); значения без дробной части допустимы (`5`); ввод нуля или значения больше 50 отклоняется.
- **Приращение 0**: допустимо — все проливы одинаковой длительности.
- **Отмена на середине ввода**: файл не создаётся, частичные данные нигде не остаются.
- **Выход из приложения во время ввода**: черновик не сохраняется, при следующем запуске форма начинается с чистого листа (с предзаполненными значениями по умолчанию).
- **Повреждённый `.tea`-файл, выбранный через браузер**: карточка не открывается, показывается сообщение о некорректном пресете, пользователь возвращается к выбору файла.
- **Файл `.tea` больше допустимого размера**: считается некорректным, приложение не зависает.
- **Открытие файла из папки вне каталога приложения**: невозможен — навигация ограничена каталогом приложения и его подкаталогами.
- **Два пресета с одинаковым названием чая в разных файлах**: оба доступны, различаются именем файла.
- **Быстрые повторные нажатия на клавиатуре**: ввод не дублируется, значение не «улетает».
- **Разряженная батарея во время создания пресета**: незавершённое создание не приводит к появлению частично записанного файла.

## Requirements *(mandatory)*

### Functional Requirements

**Выбор пресета**

- **FR-001**: Приложение ДОЛЖНО иметь главное меню с двумя пунктами: выбор пресетов и создание нового пресета; главное меню — единственное место, откуда начинается работа.
- **FR-002**: Пункт выбора пресетов ДОЛЖЕН открывать стандартный системный экран выбора файла (тот же компонент, что в приложении-примере в разделе «File Select»), а не собственный список.
- **FR-003**: Экран выбора файла ДОЛЖЕН открываться в каталоге приложения и показывать только файлы `.tea` и подкаталоги этого каталога.
- **FR-004**: Пользователь ДОЛЖЕН иметь возможность перемещаться по подкаталогам каталога приложения вверх и вниз, но не выходить за его пределы.
- **FR-005**: При выборе `.tea`-файла приложение ДОЛЖНО показывать карточку пресета с названием, граммовкой, временем первого пролива, приращением, рекомендованным числом проливов и действием Start.
- **FR-006**: При выборе файла, который не прошёл проверку, приложение ДОЛЖНО показать понятное сообщение и вернуть пользователя к экрану выбора файла, не открывая карточку.
- **FR-007**: Если каталог приложения отсутствует или в нём нет `.tea`-файлов, приложение ДОЛЖНО сообщить об этом и предложить создать пресет.

**Создание пресета**

- **FR-008**: Пункт «New preset» ДОЛЖЕН запускать пошаговый ввод: название → граммовка на 100 мл → время первого пролива → приращение → рекомендованное число проливов → сводка → сохранение.
- **FR-009**: Название ДОЛЖНО вводиться стандартной экранной клавиатурой устройства; допускаются латинские буквы, цифры, пробел и `_`, длина до 24 символов.
- **FR-010**: Числовые значения ДОЛЖНЫ вводиться экранным цифровым вводом; граммовка допускает одну точку как десятичный разделитель.
- **FR-011**: Каждое числовое поле ДОЛЖНО быть предзаполнено типичным значением (граммовка 5.0, первый пролив 20 с, приращение 5 с, число проливов 6), чтобы пользователь мог быстро исправить нужное.
- **FR-012**: Приложение ДОЛЖНО проверять каждое значение при подтверждении шага: граммовка 0.1–50, первый пролив 1–3600 с, приращение 0–600 с, число проливов 1–99; значения вне диапазона ДОЛЖНЫ отклоняться с сообщением о допустимом диапазоне.
- **FR-013**: Перед сохранением пользователь ДОЛЖЕН видеть сводку всех значений и подтверждать её.
- **FR-014**: При сохранении приложение ДОЛЖНО создать в каталоге приложения файл `.tea` в формате спецификации 001: имя файла образуется из названия (латиница в нижнем регистре, пробелы → `_`), расширение `.tea`; при совпадении с существующим файлом ДОЛЖЕН добавляться числовой суффикс (`_2`, `_3`, …) либо предлагаться явная перезапись.
- **FR-015**: После успешного сохранения приложение ДОЛЖНО показать сообщение с именем созданного файла и ДОЛЖНО сделать пресет доступным для выбора без перезапуска приложения.
- **FR-016**: Отмена на любом шаге ДОЛЖНА возвращать пользователя назад без создания файла и без остаточных данных.

**Правка пресета**

- **FR-017**: Из карточки пресета пользователь ДОЛЖЕН иметь возможность открыть правку: та же форма, что при создании, но заполненная текущими значениями.
- **FR-018**: При сохранении правки ДОЛЖЕН обновляться исходный файл; имя файла не меняется даже при изменении названия чая.

**Общие требования**

- **FR-019**: Все подписи интерфейса (меню, карточка, форма, сообщения) ДОЛЖНЫ быть на английском языке и помещаться на экране 128×64; длинные названия и значения обрезаются, но не вытесняют остальные элементы.
- **FR-020**: На каждом экране ДОЛЖНЫ отображаться подсказки назначения кнопок.
- **FR-021**: Ошибки чтения, записи и проверки значений ДОЛЖНЫ отображаться коротким английским сообщением с предложением действия (повторить, исправить, отменить) и НЕ ДОЛЖНЫ приводить к потере уже введённых данных.
- **FR-022**: Созданные на устройстве файлы ДОЛЖНЫ быть полностью совместимы с файлами, подготовленными на компьютере (двусторонняя совместимость формата `.tea`).
- **FR-023**: Поведение таймера на экране заваривания ДОЛЖНО полностью соответствовать спецификации 001 и не зависит от способа появления пресета (с компьютера или с устройства).

### Key Entities

- **Пресет (Preset)**: те же пять атрибутов, что в 001 (название, граммы на 100 мл, первый пролив, приращение, рекомендованное число проливов) плюс имя файла-источника.
- **Файл пресета (Preset file)**: файл `.tea` в каталоге приложения; создаётся приложением или копируется с компьютера; имя файла образуется из названия.
- **Черновик формы (Draft)**: значения, введённые пользователем до сохранения; существует только в пределах открытой формы, при отмене или выходе отбрасывается.
- **Сохранённый пресет-результат (Save result)**: имя созданного/обновлённого файла и признак, создан он заново или перезаписан — то, что показывается в сообщении об успехе.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: От запуска приложения до карточки пресета — не более 3 нажатий (меню → выбор пресетов → файл) и не более 2 секунд при 100 файлах в каталоге.
- **SC-002**: Пользователь без инструкции создаёт первый пресет за 60 секунд и не более чем за 25 нажатий.
- **SC-003**: 100 % пресетов, созданных на устройстве, читаются приложением сразу и после перезапуска, а также на компьютере как обычный текстовый `.tea`-файл.
- **SC-004**: Ни один пресет, созданный через форму, не оказывается некорректным по правилам 001 (0 % невалидных файлов).
- **SC-005**: Ни один некорректный ввод не приводит к падению или зависанию: 100 % проверенных ошибочных сценариев завершаются сообщением и возможностью продолжить.
- **SC-006**: 9 из 10 тестовых пользователей объясняют, где находится выбор пресета и где — создание нового, сразу после первого запуска.
- **SC-007**: Отмена на любом шаге в 100 % случаев не оставляет файлов и мусора в каталоге.
- **SC-008**: При правке пресета на устройстве остальные (неизменённые) значения сохраняются без потерь — в 100 % проверок.

## Решения по открытым вопросам

- **Точка входа**: главное меню из двух пунктов («Presets» и «New preset»), а не мгновенное открытие выбора файла. Плюс — понятное место для создания пресета; минус — одно дополнительное нажатие. Альтернатива, если решим иначе: выбор файла сразу при запуске, а создание — через пункт «New preset» в конце списка файлов.
- **Конфликт имён файлов**: по умолчанию не перезаписывать молча, а добавлять суффикс `_2`, `_3`; при правке существующего пресета сохраняем исходное имя файла.
- **Правка пресета**: входит в объём как отдельный сценарий P3 — форма та же, что при создании.
- **Удаление пресета** из приложения не входит в объём: файлы можно удалять любым файловым менеджером на карте.

## Assumptions

- **Стандартные компоненты**: для выбора файла и ввода текста используются штатные компоненты прошивки, уже доступные внешним приложениям (в приложении-примере это раздел «File Select»; для ввода — экранная клавиатура). Их внешний вид и поведение не переделываются.
- **Каталог**: `/ext/apps_data/tea_timer/` — тот же, что в 001; при сохранении создаётся автоматически, если отсутствует.
- **Формат `.tea`**: без изменений относительно 001 (`name`, `leaf_g_per_100ml`, `first_pour_sec`, `increment_sec`, `max_pours`).
- **Названия и кодировка**: только латинские буквы, цифры, пробел и `_`; кириллица не вводится, так как не отображается на устройстве.
- **Черновик не сохраняется**: если пользователь вышел из формы, данные теряются.
- **Навигация в браузере**: ограничена каталогом приложения и его подкаталогами.
- **Совместимость с 001**: требования 001 (таймер, инкремент, превышение лимита, уведомления, английский UI) действуют без изменений; заменяется только способ выбора пресета.
- **Референсные макеты** в `ui/` — предложение для согласования; стандартные экраны ввода и выбора файла нарисованы схематично и будут выглядеть как в прошивке.
